Add C and C++ support to devkb in this repository. Today the graph has Python, TypeScript/JavaScript and Odoo XML symbols and nothing for C or C++, so an agent working in a C++ repository gets an empty graph. Make `devkb build` put C and C++ code into the graph:

- **Files**: tracked files (`git ls-files`) ending `.c .cc .cpp .cxx .h .hh .hpp .hxx .inl`, skipping vendored directories (`third_party`, `vendor`, `external`, `build`, `node_modules`).
- **Symbols**: `Symbol` nodes for function and method *definitions* (free functions, methods defined in a class body, `Class::method` defined out of line, constructors, destructors, operators, function templates) and for `class`/`struct`/`union` (kind `class`) and `enum` (kind `enum`) definitions, nested in namespaces and classes. Natural key `<repo-relative path>::<qualified name>` with the qualified name joined by `.` including namespaces and classes (`geo.Shape.reset`, `leveldb.ReadBlock`; a destructor is `geo.Shape.~Shape`, an operator `geo.Shape.operator==`). `kind` is `function` (free), `method`, `class` or `enum`; set `line_start` and `line_end`. A `DEFINED_IN` edge to a `File` node, as the other languages do. Text inside comments, string literals and preprocessor lines must never produce a symbol. Declarations without a body produce no symbol.
- **Calls**: `CALLS` edges between those symbols, found inside function bodies, with `confidence` below 1 and an `evidence_ref`. Precision before recall: when a call could mean more than one symbol, or the receiver's type is unknown and the name is not unique in the repository, add no edge. A bare call from a method prefers the same class. A call qualified `A::b()` matches `A.b`. A bare call to a name that only exists as a method of an unrelated class is not an edge.
- **Tests**: `devkb/test_discovery.py` finds GoogleTest (`TEST`, `TEST_F`, `TEST_P`), Boost.Test and Catch2 cases in `*_test.cc`, `*_test.cpp`, `test_*.cc`, `test_*.cpp` files: `tests_in_file(repo, rel)` returns `("Suite.Name", line)` pairs (Catch2: the case title), and `list_test_files` includes those files. A test macro is a test case, not a function Symbol.
- **Scale**: no new dependency (standard library only; no tree-sitter, no clang). A large C++ repository must build in seconds: the three public checkouts below each build in under 20 seconds.
- Update `README.md`'s language table and `SCOPE.md` to say it, with what it cannot do (no preprocessor expansion, no overload resolution, no type inference).

Write tests with small fixture repositories (git init in a temp directory). Run the full suite with `python -m pytest tests -q`; it must pass.
