# Benchmark: lattice-scan, 2026-11-14

devkb on a repository the paper's study never saw: [namiq-ai/lattice-scan](https://github.com/namiq-ai/lattice-scan)
(a command-line tool, Apache-2.0) at commit `17e2aefd`. Exploratory, not pre-registered.

## Setup

- **Tasks**: 12, generated by `devkb/bench/cli_tasks.py` (seed 2029) with truth from source, never from the graph:
  4 error traces (`rca`: the raiser, every function that reaches it, the test files) and 8 refactor scopes (every file
  with a direct caller, the test files among them). `tasks.packs.json` holds tasks, truth and packs.
- **Arms**: `plain` (search and read only), `core` (12 single-question devkb tools), `lean` (7 tools), `pack` (a pre-computed pack in
  the prompt, no tools). Graph arms were told to use the graph first.
- **Protocol**: Sonnet in every arm, 5 repetitions, every arm in one shuffled session, a discarded warm-up per arm,
  40-turn cap. 240 runs, all valid, $12.60.
- **Caveat**: the error pack was fixed during this dogfooding, before the run (it now lists every function that
  reaches the raiser). The run measures the fixed pack.

## Results

Cost saved against plain (positive means cheaper) and quality difference, 95% bootstrap intervals resampling runs
within task (`report.json`, from `study/analysis/analyze.py`):

| Arm | Cost saved | Quality difference | Mean score |
|---|---|---|---|
| plain | — | — | 0.909 |
| core | +13% [+2, +23] | +0.022 [+0.009, +0.035] | 0.931 |
| lean | +36% [+27, +45] | +0.052 [+0.041, +0.062] | 0.961 |
| pack | **+51%** [+43, +59] | **+0.058** [+0.048, +0.065] | 0.967 |

| Task kind | core | lean | pack |
|---|---|---|---|
| error trace (4) | +24% cost saved, +0.063 quality | +47%, +0.153 | **+60%, +0.172** |
| refactor scope (8) | −21% [−54, +6], +0.001 | +5% [−25, +29], +0.001 | +26% [0, +46], +0.001 |

Tokens by kind, median run (`tokens.md`):

| Arm | Turns | Input + cache write | Cache read | Output | Context processed | Context saved |
|---|---|---|---|---|---|---|
| plain | 3 | 6,529 | 75,104 | 677 | 77,844 | — |
| core | 6 | 2,414 | 132,180 | 884 | 133,288 | −2% |
| lean | 4 | 1,376 | 76,354 | 618 | 76,414 | +26% |

## Reading

- The pattern of the paper's confirmatory study holds on an unseen codebase: packs saved 41% there and 51% here, the
  lean tools 35% and 36%.
- The saving is in chains: on error traces plain search found only part of the call chain (callers F1 0.69 against
  0.83 for lean and pack, over all 20 runs per arm). On one-hop refactor scoping, quality is equal everywhere and the full tool set costs more,
  the per-call overhead the paper describes.
- The core arm processed more context than plain yet cost less: plain writes new file contents into the cache, core
  re-reads cached context, the cheapest kind.
- 12 tasks on a small repository: the intervals are indicative.

## Reproduce

```bash
.venv/bin/python -m devkb.bench.pipeline prepare lattice-scan     # graph, tasks, packs (free)
.venv/bin/python -m devkb.bench.pipeline run lattice-scan --arms plain,core,lean,pack --reps 5 --model sonnet
.venv/bin/python -m devkb.bench.pipeline report lattice-scan --model sonnet
```

The run above used the harness before `pipeline` existed, with seed 2029 and the same arms; `runs.jsonl` is its raw
output (answers included; the repository is public).
